# Publishing the editor packages

Most packages work straight from this repository (see each directory's
README). Publishing them in the editors' own registries needs an account
or a pull request to another project, so these steps are done by hand.

## Visual Studio Code: Marketplace and Open VSX

Every release builds `brim-vscode-X.Y.Z.vsix` and attaches it to the
GitHub release, so it can be installed with
`code --install-extension brim-vscode-X.Y.Z.vsix`. To publish it in the
marketplaces as well:

1. Create the publisher `ordnary` on <https://marketplace.visualstudio.com/manage>
   (it matches `publisher` in `vscode/package.json`), and an Azure DevOps
   personal access token with the **Marketplace > Manage** scope.
2. Create an account on <https://open-vsx.org>, sign the publisher
   agreement, create the namespace `ordnary` and an access token.
3. Store the tokens as repository secrets `VSCE_PAT` and `OVSX_PAT`
   (**Settings > Secrets and variables > Actions**).

From then on every release publishes the extension to both. VSCodium,
Cursor and Windsurf install from Open VSX.

## Homebrew

The tap is `ordnary-com/homebrew-tap`: `brew install ordnary-com/tap/brim`.
`scripts/homebrew-formula.sh X.Y.Z` writes the formula for a release. To
let releases update it themselves, create a fine-grained token with
**Contents: read and write** on `ordnary-com/homebrew-tap` and store it
as the secret `HOMEBREW_TAP_TOKEN`.

## Zed

Zed lists extensions from <https://github.com/zed-industries/extensions>.
Their AI policy requires a person to open the pull request, write its
description and answer review questions in their own words, and to have
tested the extension in Zed at the submitted commit (**zed: install dev
extension**, choose `editors/zed`). `editors/zed` has the license file
their CI requires.

1. Fork it and add this repository as a submodule:
   `git submodule add https://github.com/ordnary-com/brim extensions/brim`.
2. Add to `extensions.toml`:
   ```toml
   [brim]
   submodule = "extensions/brim"
   path = "editors/zed"
   version = "0.1.0"
   ```
3. Run `pnpm sort-extensions` and open a pull request.

The `rev` in `zed/extension.toml` must point at a commit that contains
the grammar.

## Neovim (nvim-treesitter)

Not yet: nvim-treesitter only takes parsers for filetypes Neovim already
detects (which goes through Vim first: `runtime/autoload/dist/ft.vim` in
vim/vim), that are "feature complete, tested by users", and whose grammar
CI uses the upstream `tree-sitter/workflows` and a `ts_query_ls` check.
Revisit once Brim has users.

Until `brim` is in nvim-treesitter, `editors/neovim` registers the parser
itself. To add it upstream, open a pull request to
<https://github.com/nvim-treesitter/nvim-treesitter> that adds `brim` to
`lua/nvim-treesitter/parsers.lua` (url `https://github.com/ordnary-com/brim`,
location `editors/tree-sitter-brim`) and the queries to `queries/brim/`.

## Helix

Submitted: <https://github.com/helix-editor/helix/pull/16384>. To update
it, or for a later language change, open a pull request to
<https://github.com/helix-editor/helix> that adds the `[[language]]` and
`[[grammar]]` entries from `helix/languages.toml` to its `languages.toml`
and the queries in `helix/runtime/queries/brim` to `runtime/queries/brim`.

## tree-sitter-brim on npm and crates.io

Tools that load grammars from package registries need
`editors/tree-sitter-brim` published there (`npm publish` from that
directory, with bindings generated by `tree-sitter init`).
